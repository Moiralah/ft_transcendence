Secrets in Vault: how it all ties together

Every secret lives only in Vault on solsys. Teammates build and run the app on their own laptop with make up (at https://localhost:8443), and make deploy updates https://ft.natscho.my. Both fetch the secrets from Vault; no secret file is kept anywhere.

2 · The commands

Same names the team already uses, so habits don't change; make deploy and make unseal are new.

Anyone · on their laptop

make up

  1. Checks WireGuard is on (Vault reachable at 10.8.0.1:8200)
  2. Logs you in to Vault if today's token expired (your username + password)
  3. Fetches the dev secrets into memory (laptops can't read production)
  4. Builds and starts the containers with them

→ the app at https://localhost:8443. make down stops it; the secrets go with it.

Tiara · from her laptop

make deploy

  1. Connects to solsys (ssh solsys)
  2. Runs make prod there: pulls the latest branchsaurus, checks Vault is unsealed, builds, starts the production stack, gives the backend a fresh Vault login, restarts the WAFs
  3. Runs waf/test-waf.sh against the live site

→ https://ft.natscho.my is updated and verified, in one command.

Any share holder · only after solsys reboots

make unseal

  1. solsys supplies its own share automatically
  2. Asks one person (Tiara, Moira, Jon or Yiwei) to type their share (never stored)
  3. 2 of 5 shares → Vault unlocks
  4. Starts the production stack (same as make prod)

→ until this runs, nobody (laptops or production) can read the secrets. Any one teammate can do it.

5 · Decisions (2026-10-08)

🧭
Access path: A · WireGuard. Vault is never on the internet; each teammate gets a personal WireGuard key (one-time setup) and turns it on before make up. To check first: that WireGuard works from the 42 campus network.
🧪
Laptops get a separate dev set. secret/family-tree/dev points at a second Supabase project (free tier) for development; laptops can't read secret/family-tree/prod, so a lost laptop or a local test can never touch production. A copy of production data can be loaded into dev when needed.
🔑
Unseal: 5 shares (Tiara, solsys, Yiwei, Jon, Moira), any 2 unlock. After a reboot, solsys adds its own share, so any one teammate can bring Vault back alone: convenient, no waiting for a second person. The accepted cost: solsys's share sits on the same machine as the encrypted data, so someone who gets into solsys and obtains one person's share could unlock everything. Mitigations: solsys's share is a root-only file outside Vault's data, each person keeps their share offline, and every unseal is logged.
🛟
Evaluation-day fallback. If solsys or the home internet fails during the evaluation, both the live site and every make up stop. Keep a sealed, offline copy of what's needed to run the demo (held by Tiara).
